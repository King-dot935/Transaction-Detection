# 怎么连到数据库

现在系统用的就是数据库：**SQLite**，文件是 `demo_dazhu/sentinel.db`。
「连接数据库」取决于你想做哪件事，三条路完全不同：

| 你的目的 | 走哪条 | 难度 |
|---|---|---|
| 我想看看里面有什么、跑几条 SQL | A. 直接连 SQLite 文件 | 5 分钟，不用改代码 |
| 我要换成 MySQL / PostgreSQL | B. 迁移到数据库服务器 | 半天，改三处代码 |
| 我要让网页直接读写数据库 | C. 走 HTTP 接口，不要直连 | 已经做好了 |

## A. 只想看数据、跑 SQL（现在就能做）

### A1 图形工具（推荐）

- **DB Browser for SQLite**：打开 → `sentinel.db` → 「浏览数据」看表，「执行 SQL」跑查询
- **VS Code 插件 SQLite Viewer**：右键 `.db` 文件直接看
- **DBeaver**：选 SQLite，连文件

常用几条：

```sql
-- 今天判了什么
SELECT ts, tier, rule_type, substr(text,1,30) FROM judge_logs ORDER BY id DESC LIMIT 20;

-- 待复核还有多少
SELECT COUNT(*) FROM review_queue WHERE status='pending';

-- 人工改判了哪些
SELECT text, rule_type, status, reviewer FROM review_queue WHERE status<>'pending';

-- 生成过的介入单
SELECT case_no, ts, substr(text,1,24) FROM cases ORDER BY id DESC;
```

### A2 命令行 / 代码

```bash
# Python 一行（不需要装任何东西）
python -c "import sqlite3;c=sqlite3.connect('demo_dazhu/sentinel.db');print(c.execute('select count(*) from judge_logs').fetchone())"
```

```python
# 在代码里
import sqlite3
conn = sqlite3.connect("demo_dazhu/sentinel.db")
conn.row_factory = sqlite3.Row
for r in conn.execute("SELECT * FROM review_queue WHERE status='pending'"):
    print(r["text"], r["reason"])
```

## B. 换成 MySQL / PostgreSQL

### 第 1 步：建库建表

```bash
mysql -u root -p < demo_dazhu/sql/mysql_schema.sql
# 或
psql -U postgres -f demo_dazhu/sql/postgres_schema.sql
```

两个脚本都已经按当前 schema 翻译好了（`sql/mysql_schema.sql`、`sql/postgres_schema.sql`），
字段类型和现有一致，**时间字段保持 VARCHAR(32)**，这样应用代码不用动类型。

### 第 2 步：装驱动

```bash
pip install pymysql              # MySQL
pip install "psycopg[binary]"    # PostgreSQL
```

### 第 3 步：配 DSN

```bash
set DATABASE_URL=mysql://root:密码@127.0.0.1:3306/sentinel
# 或
set DATABASE_URL=postgresql://user:密码@127.0.0.1:5432/sentinel
```

验证：

```bash
python db_connect.py %DATABASE_URL%
```

### 第 4 步：导数据（可选）

```bash
python export_data.py            # 先导成 CSV
```

然后用 MySQL Workbench / DBeaver 的「导入 CSV」逐表导入，或 `LOAD DATA INFILE`。

### 第 5 步：改代码（只有三处）

`db.py` 里需要改的其实很少：

| 改哪 | 现在（SQLite） | 改成 MySQL / PG |
|---|---|---|
| `connect()` | `sqlite3.connect(DB_PATH)` | `pymysql.connect(...)` / `psycopg.connect(dsn)` |
| 占位符 | `?` | `%s`（两种都是） |
| 自增 id | `INTEGER PRIMARY KEY AUTOINCREMENT` | 见 SQL 脚本，已处理 |

`db.py` 里所有 SQL 都用 `?` 占位符，可以写一个 3 行的包装：

```python
class DB:
    def __init__(self, dsn): self.conn, self.kind = db_connect.connect(dsn)
    def execute(self, sql, params=()):
        if self.kind != "sqlite":
            sql = sql.replace("?", "%s")
        return self.conn.cursor().execute(sql, params)
    def commit(self): self.conn.commit()
```

### 第 6 步：验证

```bash
python db_connect.py %DATABASE_URL%   # 表行数对得上
python demo.py                        # 页面能正常读写
python validate_data.py               # 数据校验通过
```

**最容易踩的坑**：MySQL 默认字符集不是 utf8mb4 的话，中文会变问号。
建库语句里已经写死 `utf8mb4_0900_ai_ci`，别改。

## C. 让网页连数据库？——不要直连

浏览器不能、也不应该直接连数据库：连接串会暴露在前端代码里，任何人都能拖库。

正确做法就是我们现在的架构：

```
浏览器  ──HTTP──▶  demo.py（后端）  ──SQL──▶  sentinel.db
                    ↑
              权限校验、参数化查询、限流都在这一层
```

- 前端只调 `/api/review`、`/api/metrics`、`/api/cases` 这些接口
- 后端负责拼 SQL、做校验
- 数据库永远不暴露到公网

`mvp/app.html` 是纯静态原型，它**不连库**，判定用的是页面内置的示例规则。
真实读写都在 `demo_dazhu` 的服务里。这也是为什么原型里那个「在审核管理打开」的按钮
跳的是 `http://127.0.0.1:8765/review`，而不是直接跳数据库。

## D. 一张图看懂现在的数据在哪

```
demo_dazhu/
├── data/                    ← 配置类数据（文件版，git 可管）
│   ├── rules.jsonl          规则库 12 条
│   ├── clauses.jsonl        知识库 28 条
│   └── scenarios*.jsonl     标注集 30 段（含当前未调参验收集）
├── sentinel.db              ← 运行数据（SQLite 文件）
│   ├── judge_logs           每次判定
│   ├── review_queue         待复核 / 已裁决
│   ├── cases                介入单
│   ├── notifications        消费者通知
│   ├── merchants            商家违规计数
│   ├── rule_candidates      规则候选池
│   ├── feedback             用户反馈
│   └── eval_runs            评测历史
├── sql/                     ← 换库用的 DDL
└── db_connect.py            ← 用 DSN 验证连接
```

**建议**：配置类数据继续放文件（改一次 diff 看得见），运行数据尽早迁到数据库服务器。
现在 SQLite 单机够用，但 `judge_logs` 是只追加的表，量起来会很快。
