# 接模型：千问判简单、DeepSeek 判复杂

系统里判定分三层，模型只负责中间两层：

```
规则（0 成本）→ 千问 qwen-plus（简单）→ DeepSeek（复杂）
```

哪一层由 `router.py` 决定，依据是**不确定性**，不是句子长短：

| 情况 | 走哪层 |
|---|---|
| 高严重度命中、或毫无风险信号 | 规则，不调模型 |
| 命中但含糊（引用条款/加条件）、或含风险词 | **千问** |
| 千问置信 < 0.75，或判成高风险类型 | **DeepSeek** |
| 模型没配 / 调用失败 | 回落规则，并进待复核队列 |

---

## 三步接入

### 第 1 步：复制配置模板

把 `demo_dazhu/.env.example` 复制成 `demo_dazhu/.env`（同一个目录）。

### 第 2 步：填 key

```ini
# 小模型 · 简单问题（阿里云百炼）
LLM_SMALL_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_SMALL_KEY=sk-你的千问key
LLM_SMALL_MODEL=qwen-plus

# 大模型 · 复杂问题（DeepSeek）
LLM_LARGE_BASE=https://api.deepseek.com/v1
LLM_LARGE_KEY=sk-你的deepseek key
LLM_LARGE_MODEL=deepseek-chat
```

> `.env` 已经在 `.gitignore` 里，不会被提交到 GitHub。

### 第 3 步：重启并验证

```bash
python demo.py
```

打开 **http://127.0.0.1:8765/lab**，右上会出现「模型接入」面板：

- 显示 `2 / 2 层已接入 · qwen-plus / deepseek-chat`
- 点「用一句样本测试两层」，会真实调用一次，返回**耗时与判定结果**

命令行也能验：

```bash
curl http://127.0.0.1:8765/api/llm/status
curl -X POST -H "Content-Type: application/json" -d "{}" http://127.0.0.1:8765/api/llm/test
```

## 模型怎么选

| 层 | 推荐 | 为什么 |
|---|---|---|
| 小模型 | `qwen-plus` | 便宜、中文稳、JSON 输出可靠，适合"规则没命中但含风险词"的中间地带 |
| 大模型 | `deepseek-chat` | 便宜且中文好；复杂/引用条款类想多推一步可换 `deepseek-reasoner` |

**不建议一上来就全用大模型**：按现在的分流比例，七成句子规则就能定，
剩下三成里也只有小部分需要升级——全量大模型的成本是小模型方案的 5 倍以上。

## 失败会怎样（已经处理好的）

| 情况 | 行为 |
|---|---|
| key 错 / 过期 | 返回 `HTTP Error 401`，该条回落规则判定，页面标「该层未接通」 |
| 网络超时 | `urlopen` 40 秒超时，异常被捕获，回落规则 |
| 模型返回不是 JSON | `llm.py` 会剥离代码块标记后重试解析，仍失败则记为「解析失败」 |
| 该层没配 | 直接返回 `None`，**不编造答案** |

**关键原则：模型是可选的增强，不是必需依赖。** 没配、配错、超时，系统都还能跑，
只是退回规则判定并把不确定的样本挂进人工复核。

## 想换别的模型

改 `.env` 里的 `BASE / KEY / MODEL` 就行，`llm.py` 走的是 OpenAI 兼容协议：

- 换成智谱：`https://open.bigmodel.cn/api/paas/v4`，模型 `glm-4-flash`
- 换成豆包：火山方舟的兼容地址，模型 `doubao-...`
- 换成自建：任何 OpenAI 兼容网关

不需要改代码。

## 成本参考（当前分流比例下）

按 1000 条样本估算：约 250 次千问 + 30~50 次 DeepSeek。

具体单价以各平台官网为准，这里只提醒一件事：
**先把「待复核率」从 12% 降到多少作为验收标准**，再判断这笔钱值不值。
如果只降到 10%，说明这批样本本来就难，钱花得不值。
