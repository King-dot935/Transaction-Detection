# 评测体系

评测需要验证三项能力：

1. 该介入的对话是否被及时发现？
2. 正常对话是否被错误打断？
3. 类型和首轮位置是否正确，且结果能否复现？

项目不使用单独一个“准确率”作为主结论，因为标注集正负样本不平衡，且误报与漏报的业务成本不同。

## 1. 数据切分

当前共有 30 段对话：

| 集合 | 正例 | 负例 | 当前用途 |
|---|---:|---:|---|
| `scenarios` | 10 | 2 | 开发集 |
| `holdout` | 4 | 2 | 历史污染，仅供复盘 |
| `holdout2` | 4 | 2 | 历史污染，仅供复盘 |
| `holdout3` | 4 | 2 | 当前未调参验收集 |

历史上曾根据 `holdout` 和 `holdout2` 的失败修改规则，因此它们不再是留出集。这个错误不应靠改标签掩盖，而应保留在报告中作为方法论教训。

## 2. 指标定义

```text
召回率 = TP / (TP + FN)
误报率 = FP / (FP + TN)
精确率 = TP / (TP + FP)
类型准确率 = 类型判对的 TP / 所有判中的 TP
首轮准确率 = 首轮位置判对的正例 / 所有判中的正例
平均发现轮次 = 判中的正例首次介入轮次均值
```

每个指标必须同时给出：

- 分子和分母。
- 数据集名称。
- 样本量。
- 置信区间或“样本不足”提示。

Wilson 区间用于二项比例。2 条负例零误报不能证明误报率低于 5%；按 rule of three 估算，95% 上界约为 150%，但概率上限只能取 100%。

## 3. 当前结果

最新可复现结果：

| 指标 | holdout3 |
|---|---:|
| 正例 | 4 |
| 负例 | 2 |
| TP / FN | 1 / 3 |
| FP / TN | 0 / 2 |
| 召回 | 25% |
| 误报 | 0% |
| 召回 Wilson 95% CI | 约 5%–70% |
| 误报 Wilson 95% CI | 约 0%–66% |

不能对外写成“误报率 0%”。正确表述是：

> 在仅 2 条负例的未调参集中观察到 0 次误报，样本不足以估计真实误报率。

## 4. 回归门禁

门禁只使用未调参集合：

| 检查 | 阈值 | 当前 | 结果 |
|---|---:|---:|---|
| holdout3 召回 | ≥ 70% | 25% | FAIL |
| holdout3 误报率 | ≤ 5% | 0%，n=2 | 不可证明 |
| holdout3 负样本数 | ≥ 60 | 2 | FAIL |
| ID/商家原话跨集合重复 | 0 | 0 | PASS |

因此总体门禁为 **FAIL**。这是有意义的失败结果，不应把开发集或污染集合加回门禁来“修成 PASS”。

## 5. 缺陷定位

`eval_suite.py` 输出四类信息：

1. 集合级指标。
2. 按类型、商家句长、是否含条款词切片。
3. 漏判、误报、类型错的结构化缺陷。
4. 在线与离线信号并列展示。

当前 holdout3 的三条漏判：

| ID | 表达 | 期望 | 根因初判 |
|---|---|---|---|
| P01 | 五星换退运费 | 以利益换好评 | 交换关系未被规则或路由识别 |
| P03 | 财务不在、下周再说 | 反复拖延 | 规则没有覆盖该类语义 |
| P04 | 再闹就封号 | 威胁或辱骂 | 风险词表缺“封”，模型未被调用 |

根因必须区分：

- 规则未命中。
- 规则命中但被负向抑制。
- 规则命中但阈值未满足。
- 路由没有把句子送去模型。
- 模型返回错误或低置信。
- 数据标签或评测口径错误。

## 6. 切片

切片用于避免“总体指标掩盖局部失效”。当前支持：

- 类型切片。
- 商家最长句长度切片。
- 是否出现条款、规定、原则上等表达。

切片样本少于 2 条时只展示计数，不给比例结论。

## 7. 在线评估

在线侧可计算：

- 判定量。
- 缓存命中率。
- 待复核率。
- 人工改判率。
- 用户反馈中的误报数。
- 分层分布和延迟。

在线指标有明确限制：

- 手输和回放样本不是真实流量。
- 人工裁决样本天然偏向“机器不确定”的分布。
- 反馈用户是自选择样本，不能代表全部用户。
- 缺少退款、投诉等下游结果，因此不能计算真实业务收益。

## 8. 正确迭代闭环

```text
开发集调规则
  → 全量回归，检查已有类型是否退化
  → 用未调参验收集跑一次门禁
  → 记录失败和根因
  → 不根据验收集直接补词
  → 扩新数据/改语义方案
  → 建立新的未调参验收集
```

只有“验收集只用于验收”这一纪律被持续执行，指标才有意义。

## 9. 复现命令

```powershell
python validate_data.py
python run_eval.py
python eval_suite.py --no-save
python metrics.py
python badcase_cluster.py
```

`run_eval.py` 当前退出码为 1，表示门禁失败。CI 应保留该退出码，不能把 `|| exit 0` 当成修复。

## 10. 结论

这个项目的评测价值不在“跑出高分”，而在：

- 发现并承认历史留出集污染。
- 把未标注与负样本分开，避免在线指标失真。
- 对仅 4 条正例、2 条负例的结果做区间解释。
- 让门禁真实失败，并把失败转成可验证的工程待办。
