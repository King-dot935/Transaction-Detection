# 切块策略

> 三类数据三种切法，因为它们服务的目的不同：会话要切成**判定单元**，知识要切成**检索单元**，
> 规则要切成**配置单元**。用同一套切法会出事。

---

## 一、会话侧：三级切块（判定单元）

```
一次会话（session）
  └── 一条消息（message）        ← 商家发一次 = 一条
        └── 一个分句（clause）    ← 按标点切，判定真正发生在这一级
```

### 1.1 第一级：会话

按 `session_id` 聚合，维护累计计数（`repeat_threshold` 用它）。
例如「反复拖延」需要连续 3 次才成立——**切块后仍要保留会话级的计数**，否则 R07 永远触发不了。

### 1.2 第二级：消息

一条商家消息 = 一个候选单元。只处理 `role=merchant`，消费者说的话不进判定。

### 1.3 第三级：分句（关键）

用 `chunking.split_clauses()` 按标点切开：

| 参数 | 值 | 说明 |
|---|---|---|
| 切分符 | `，。；！？,;!?、\n` | 中英文标点都切 |
| 最短片段 | 2 字 | 低于这个长度的碎片（「嗯」「啊」）直接丢弃 |
| 切完为空 | 回退成原文一条 | 不能因为切块把内容丢了 |

### 1.4 为什么必须切到分句

旧逻辑是**整条消息**先过负向抑制：只要出现「可以退 / 已经安排」就整条放行。
商家只要把承诺和要挟放进同一条消息，就能绕过判定：

| 消息 | 旧（整条） | 新（分句） |
|---|---|---|
| `可以退，你先把差评删了` | **不介入**（漏判） | R04 介入 |
| `已经安排退款，你把差评删掉` | **不介入**（漏判） | R04 介入 |
| `可以退的，您申请一下就行` | 不介入（对） | 不介入（对） |

第三行说明切块**没有放松抑制**：分句级抑制仍然把真正正常的承诺放过去了。

### 1.5 跨句例外：哪条规则不做分句切

`R01 拒绝法定权利` 是「权利词 + 拒绝词」的组合，两者经常不在同一分句：

> 「我要退货」……「这个不退」

如果按分句判，两边各缺一半，永远命中不了。所以 **R01 看整条消息**。

**规则表里的取法**：`rights` / `denials` 字段 → 整条消息范围；`patterns` 字段 → 分句范围。

### 1.6 副作用与验证

改完重跑 `run_eval.py`。当前口径下，开发集和两组历史留出集已参与调参，不能再用它们的 100% 证明泛化；唯一未调参的 holdout3 召回为 25%，因此门禁仍为 FAIL。切块改动本身不应改变判定语义，验证时要同时检查回归集和未调参集。
说明切块修的是漏判，没有带来新的误报。

## 二、知识库：按条款原子化（检索单元）

### 2.1 现状：一条 = 一个条款

`clauses.jsonl` 现有 28 条，是**人工原子化**的结果：

```json
{"id":"RETURN_7.1","title":"七天无理由退货的适用范围",
 "text":"自营商品在签收后 7 日内可申请无理由退货…",
 "scope":"自营、非定制类","exceptions":[],"risk_level":"low"}
```

一条条款 = 一个可独立引用的规则单元，**不做滑窗、不做重叠**。

### 2.2 为什么不用固定长度滑窗

滑窗（如 300 字一块、重叠 50 字）适合连续叙述型文档（论文、说明书）；
平台规则是**编号结构**的，条款边界本身就是语义边界。切在中间会出现：

> 「不得以退换货、补偿等利益，换取消费者修改」——后半句「或删除评价」跑到下一块去了

提示卡引用这种半句，用户会看得一头雾水。**按条款号切，比按字数切准。**

### 2.3 接入长文档时的切块流程（已实现：chunk_doc.py）

现在的 28 条是手写的。如果要导入《平台规则》全文，走这条流水线：

```
原始文档（Word / PDF / 网页）
  → ① 抽取正文（去页眉页脚、去导航）
  → ② 按条款号正则切：^第[一二三四五六七八九十百]+条|^\d+\.\d+
  → ③ 每条生成 id：域_条款号（如 RETURN_7.1）
  → ④ 校验：必须含 title + text + scope，缺 scope 的人工补
  → ⑤ 长度上限 300 字，超长的按「①②③」子项拆
  → ⑥ 重叠 = 0（条款之间不重叠，靠 id 关联）
  → ⑦ 落 clauses.jsonl，跑 check_catalog.py
```

### 2.4 实现与实测

`ash
python chunk_doc.py data/sample_rules.md          # 预览
python chunk_doc.py data/sample_rules.md --write  # 写入 data/clauses_imported.jsonl
`

样例文档切出来的结果：

| id | 标题 | 字数 | scope |
|---|---|---:|---|
| RETURN_7 | 七天无理由退货 | 42 | 自营商品 |
| RETURN_8 | 已使用商品的退货 | 37 | 全部品类 |
| FREIGHT_9 | 退货运费承担 | 58 | 全部品类 |
| EVAL_10 | 评价的独立性 | 47 | 全部品类 |
| INVOICE_11 | 发票开具 | 49 | 全部品类 |
| TRANS_12 | 平台内完成交易 | 42 | 全部品类 |

**两个踩过的坑**：

1. 「评价的独立性」正文里有「退换货」，按关键词顺序第一次被判成 EXCHANGE。
   → 改成标题命中权重 3、正文权重 1 打分，修好。
2. 「退货运费承担」里 RETURN 和 FREIGHT 同分，被判成 RETURN。
   → 加一条中文中心词规则：标题里命中位置越靠后越可能是中心词，FREIGHT_9 修好。

**边界**：切出来的条款写进 clauses_imported.jsonl，**不直接进正式知识库**。
人工评审（改 id、补 scope、确认例外）之后再合并进 clauses.jsonl。
域推断终究是启发式的，机器给候选、人拍板。

### 2.5 元数据是切块的一部分

| 字段 | 作用 |
|---|---|
| `id` | 被规则引用，也是可追溯的锚点 |
| `title` | 检索与展示用，用户看标题比看全文快 |
| `scope` | 适用范围（自营/定制/大件），**防止条款套错场景** |
| `exceptions` | 例外项，说明特殊情况的适用条件 |
| `risk_level` | 决定提示卡的视觉强度 |

一个块没有 `scope` 就等于没有边界，引用出去会误导用户。

## 三、规则库：按"不公平类型"切（配置单元）

### 3.1 一条规则 = 一个类型

不是按文本切，是按**语义类型**切：诱导线下交易、以利益换好评、威胁辱骂……

同一种类型的所有说法（「加微信」「加v」「私聊」「私下转」）放进**同一条规则的 `patterns` 数组**，
它们是同义表达集合，不是文本块。

### 3.2 为什么不按句长或频率切

- 按长度切：把「拆封不退」和「拆开就不退」切成两条规则，结果同一句话命中两条，还得再裁决
- 按频率切：高频说法单独成条会让规则数膨胀，而判定结果完全一样

**切规则的唯一标准是"这句话该被判成什么类型"**，不是它有多长、多常见。

### 3.3 三种字段对应三种切块范围

| 字段 | 切块范围 | 例子 |
|---|---|---|
| `patterns` | 分句 | R04「删差评」 |
| `rights` + `denials` | 整条消息 | R01「退」+「不退」 |
| `negative: true` | 分句（抑制该分句） | R12「可以退」 |

### 3.4 冲突靠优先级裁决，不靠切得更细

一个分句同时命中 R02（扩大退货例外）和 R01（拒绝法定权利）时，
按「严重度 → priority」取第一条，而不是继续切块去区分。

## 四、三者对比

| | 会话侧 | 知识库 | 规则库 |
|---|---|---|---|
| 切出来是什么 | 判定单元 | 检索 / 引用单元 | 配置单元 |
| 切法 | 按标点分句 | 按条款号 | 按不公平类型 |
| 边界来源 | 语法（标点） | 文档结构（第 X 条） | 语义（这算哪种违规） |
| 重叠 | 无 | 无 | 无 |
| 由谁维护 | 系统自动 | 法务 / 规则运营 | 产品 + 风控 |
| 切错的后果 | 漏判（承诺与要挟混在一句） | 引用半句话，用户看不懂 | 同一句命中多条，裁决变复杂 |

## 五、参数一览

| 参数 | 位置 | 值 |
|---|---|---|
| 分句切分符 | `chunking.SPLIT_RE` | `，。；！？,;!?、\n` |
| 最短分句 | `chunking.MIN_LEN` | 2 字 |
| 单条消息上限 | `preprocess.MAX_LEN` | 500 字（超出截断并标记） |
| 条款块上限 | 切块流水线 | 300 字（超出按子项拆） |
| 条款间重叠 | — | 0 |
| 会话级累计阈值 | 规则的 `repeat_threshold` | R07 为 3 |
