# 规则 / 小模型 / 大模型：怎么分工

用当前 208 条判定日志算出来的真实分布：

| 层 | 条数 | 占比 | 单条成本 | 延迟 |
|---|---:|---:|---:|---|
| 规则 | 141 | 67.8% | 0 | < 1ms |
| 小模型（千问） | 46 | 22.1% | 1 单位 | 0.3–1s |
| 人工 | 21 | 10.1% | — | 分钟级 |
| 大模型（DeepSeek） | 0（未接入） | — | 10 单位 | 2–5s |

规则命中率 45.7%，但**67.8% 的判定根本不需要模型**——因为规则不仅能"命中"，还能"确认无风险后放行"。

---

## 一、什么时候适合用「小模型」

判断标准不是句子长短，是**任务类型**。

### 适合

| 场景 | 例子 |
|---|---|
| **窄分类**：类别有限、边界清晰 | 「这句话属于拒绝退货 / 诱导线下 / 其他？」 |
| **结构化抽取**：要字段不要论述 | 「抽出：承诺动作、附加条件、金额」 |
| **规则命中但表述绕** | 命中 R01（权利+拒绝），但要判断"你先把差评删了"是否构成条件交换 |
| **含风险词但没命中规则** | "按规定我们这边一律没有票"（"没有票"不在词表里） |
| **需要稳定 JSON 输出** | 下游要直接入库，解析失败要能重试 |

### 不适合

| 场景 | 为什么 |
|---|---|
| 多轮指代消解 | "这个""那样"要回看上下文，小模型容易丢 |
| 需要条款知识做定性 | 「是否属于七日无理由的法定例外」需要外部知识 |
| 需要多步推理 | 「先承诺退、又加条件、还威胁差评」要串起来看 |
| 高严重度红线 | 漏判代价太高，宁可规则直定 + 人工兜底 |

### 一句话口诀

> **能写成关键词表 → 规则**
> **能用一句话说清判定标准 → 小模型**
> **需要两三步推理才说得清 → 大模型**
> **三步都说不清 → 人工**

---

## 二、规则不是没用了，它是三层里唯一「可审计」的

模型替代不了规则的三件事：

### 1. 可解释、可审计

介入单里要写：

> 依据：《评价的独立性》EVAL_4.2

这句话能进申诉材料、能进监管说明。**模型的理由是"参考"，不是"依据"**。
你现在点开任意一张提醒卡，看到的条款号就是规则给的。

### 2. 确定性

同样的输入，规则永远同样输出。模型有温度参数、有版本漂移、有服务波动。
**红线类判定（高严重度）必须由规则定**，不能今天判违规、明天判不违规。

### 3. 兜底

模型超时、欠费、被限流、key 过期——系统都还得跑。
当前的实现是：模型挂了就回落规则，并把不确定的挂进人工队列。

### 规则真正的短板

留出集里那条数据很说明问题：

| 类型 | 命中率 |
|---|---:|
| 照规则原话写 | **89%** |
| 换了说法 | **0%** |

规则不怕"明确的话"，怕"换个说法的同一句话"。**这正是模型该补的位置**——不是取代规则，是接住规则漏掉的那一半。

## 三、三层怎么分（当前策略）

```
                ┌─────────────┐
每一条消息  ───▶ │ 规则层       │
                └──────┬──────┘
         命中且确定    │    不确定 / 含风险词 / 未命中
        ┌─────────────┴──────────────┐
        ▼                            ▼
   直接定案                     ┌──────────┐
   带条款依据                    │ 小模型    │
   成本 0                       └────┬─────┘
                         置信≥0.75 且 │ 置信<0.75
                         判非高风险    │ 或判高风险
                    ┌──────────────┴───────────┐
                    ▼                          ▼
                直接出结论                ┌──────────┐
                                        │ 大模型    │
                                        └────┬─────┘
                                     仍不确定 │
                                             ▼
                                        人工复核
```

### 四条设计原则

**1. 只升级，不降级**
任何一条都从规则开始，规则不确定才往上升。绝不允许"先问大模型，模型说没事就放过"——那等于让最贵的层承担最强的责任。

**2. 按后果定升级线，不按长度**

| 情况 | 去哪层 | 理由 |
|---|---|---|
| 高严重度规则命中 | 规则直定 | 已经足够确定，再问模型是浪费钱 |
| 中等严重度 + 表述含糊 | 小模型 | 需要理解同义改写 |
| 含风险词但未命中 | 小模型 | 典型的"改写漏判"场景 |
| 小模型置信 < 0.75 | 大模型 | 小模型自己拿不准 |
| 小模型判成高风险类型 | 大模型 | 高风险误判代价大，值得复核 |
| 两层结论冲突 | 人工 | 机器之间打架，人来做仲裁 |

**3. 不让模型直接判「违规 / 不违规」**

模型只做**分类 + 抽取 + 置信度**，定性由规则和条款决定。

> 模型是翻译器，不是法官。

一旦让模型直接输出"违规"，你就失去了可解释性、可审计性，也失去了用规则修正它的抓手。

**4. 给大模型设预算闸门**
日预算超了就降级为「小模型 + 挂人工」，**而不是排队等额度**。用户体验比成本重要，但成本必须可控。

## 四、成本怎么算（可替换成真实单价）

当前成本单位是相对值：规则 0、小模型 1、大模型 10。

**每 1 万条消息的成本**

| 分流方案 | 规则 | 小模型 | 大模型 | 成本（单位） | 相对基准 |
|---|---:|---:|---:|---:|---:|
| 全大模型 | 0% | 0% | 100% | 100,000 | 100× |
| 规则 + 大模型 | 68% | 0% | 32% | 32,000 | 32× |
| **规则 + 小模型（当前）** | **68%** | **32%** | 0% | **3,200** | **3.2×** |
| 规则 + 小模型 + 大模型（5%） | 68% | 27% | 5% | 3,200 + 5,000 = 8,200 | 8.2× |
| 全规则 | 100% | 0% | 0% | 0 | 1× |

> 接入真实单价后，把「单位」换成实际价格即可。
> 关键结论：**大模型走 5% 的量，成本就和整个小模型层持平**——所以升级线必须严格。

## 五、怎么验证"平衡得对"

不平衡的表现是：某一层过度承载。四个可量化指标：

| 指标 | 当前值 | 目标 | 失衡信号 |
|---|---:|---|---|
| 规则命中率 | 45.7% | 45–60% | 过低 = 规则没建好；过高 = 样本太单一 |
| 待复核率 | 10.1% | < 8% | 持续升高 = 模型没接住长尾 |
| 误报率 | 5% | < 5% | 升高 = 规则太激进 |
| 单条成本 | 0 | 按预算定 | 突然翻倍 = 升级线失效 |

### 调参方法：扫阈值，不要拍脑袋

拿留出集（那 12 段没调过参的数据），把「小模型 → 大模型」的置信阈值从 0.6 扫到 0.9，每个点记录：

- 待复核率
- 召回率
- 单条成本

画三条曲线，**选召回掉得最少、成本涨得最慢的那个拐点**。这比"我觉得 0.75 差不多"靠谱。

## 六、四个常见错误

| 错误 | 后果 |
|---|---|
| 一上来全用大模型 | 成本 30 倍、延迟 5 倍，效果未必好——大部分句子规则就够 |
| 规则堆到几百条 | 互相冲突、维护成本爆炸、没人敢改 |
| 让模型直接判违规 | 不可解释、不可审计、输出有抖动，出事没法交代 |
| 用模型替代人工 | 真正的新情况没有标注，模型永远学不到 |

---

## 一句话总结

> **规则管确定的，小模型管含糊的，大模型管要推理的，人管没见过的。**
> 三层的价值不在"谁更聪明"，而在"谁能用最便宜的方式把这一段说清楚"。
