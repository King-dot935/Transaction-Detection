# 25% 是怎么来的：逐条归因

留出集三（holdout3）6 段：4 正 2 负，抓到 1 条 → **召回 25%**，误报 0%。

下面这 3 条漏判，每条的失败原因都不一样。

---

## 一、三层归因框架

一条漏判可能错在五个地方，按顺序排查：

| 层 | 含义 | 怎么判断 |
|---|---|---|
| L1 词表 | 这句话里根本没有任何触发词 | 遍历该类型的 patterns，看是否出现在原句 |
| L2 词在表里但没命中 | 匹配/切块环节的问题 | 词在句子里，`match()` 却返回空 |
| L3 阈值过严 | 命中了，但要求出现 N 次才成立 | 命中项带 `repeat_threshold > 1` |
| L4 负向抑制 | 命中了，但被"正常承诺词"压掉 | 分句里含 `_neg_patterns` |
| L5 评测口径 | 单句判不出，会话能判 | 会话累计 ≥ 阈值，单句 < 阈值 |

工具：`python diagnose.py holdout3.jsonl`

---

## 二、三条漏判的归因

### P01「亲，您先给我点个五星，运费我退您」

**归因：L1 词表——但根子是"规则类型"不够**

现有 R04 的触发词是**短语表**：

```
删差评 / 差评删 / 改好评 / 好评返现 / 五星好评 / 评价改 …
```

这句话里：
- 有「五星」，但组成的是「点个五星」（动作），不是「五星好评」（短语）
- 有「运费我退」（利益），但和「五星」分在两个分句里

**短语表匹配的是"固定说法"，这句话是"关系"**——评价动作 + 利益给予。
用词表永远抓不全，因为同一个关系的表达方式有无穷多种。

**需要的规则类型**：共现规则

```json
{
  "id": "RX1",
  "type": "以利益换好评",
  "relation": {
    "评价词": ["五星", "好评", "评价", "晒图"],
    "利益词": ["退", "返", "补", "红包", "运费", "优惠券", "返现"],
    "交换词": ["先", "才", "就", "再", "换"]
  },
  "clause": "EVAL_4.2",
  "severity": "high"
}
```

三个条件同时满足才命中——**第三个条件（交换词）是防误报的关键**：

| 句子 | 评价词 | 利益词 | 交换词 | 判定 |
|---|---|---|---|---|
| 您先给我点个五星，运费我退您 | ✅ | ✅ | ✅ 先 | 命中 |
| 五星好评，运费我们承担 | ✅ | ✅ | ❌ | 不命中（正常承诺） |

现在的引擎只支持一种组合规则（权利 + 拒绝），**没有通用的共现匹配**。

**实测这套三条件规则**（用一个独立脚本验，不碰标注集）：

| 句子 | 判定 | 说明 |
|---|---|---|
| 您先给我点个五星，运费我退您 | 命中 | 交换词「先」 |
| 五星好评，运费我们承担 | 不命中 | 没有交换语义 ✅ |
| 运费我们承担，请您放心 | 不命中 | ✅ |
| 您先给我个好评，我马上给您补发 | 命中 | ✅ |
| 把评价改一下，我这边给您退款 | **不命中** | 缺显式交换词，漏了 ❌ |

最后一条说明三条件规则**不完美**：没有「先/才/就」这类连接词的交换仍然会漏。
这类目前靠 R04 的短语表（评价改）兜住——**规则表达能力和词表覆盖是互补的，不是替代关系**。


### P03「财务今天不在，下周再说吧」+「再等等，下周一定」

**归因：L3 阈值过严**

R07（反复拖延）确实命中了「下周再说」，但规则要求 `repeat_threshold = 3`：

```
这段会话里只出现 2 次 → 不成立
```

**为什么阈值是 3**：写规则时在开发集里，拖延场景恰好有 3 次。
**问题**：真实会话平均只有 2 轮商家发言，要求 3 次等于"永远不成立"。

这是**典型的目标设定错误**——阈值应该按真实会话长度定，不是按手里那份数据定。

**修法**：阈值降为 2，或改成"2 次 + 时间跨度 > 24 小时"（更贴近"反复"的语义）。

### P04「你再闹我就让你这个号封了」

**归因：L1 词表——威胁以"后果"表达**

现有 R05 的触发词全是**固定威胁短语**：

```
你等着 / 投诉也没用 / 爱要不要 / 滚 / 废物 / 傻
```

这句话的威胁不在词上，在**结构**上：`你再…我就让你…（后果）`。
后果词（封号/封店/限制/拉黑）一个都不在表里。

**需要的规则类型**：句式规则

```json
{
  "id": "RX2",
  "type": "威胁或辱骂",
  "pattern": "(你再|敢|要是|如果)[^，。]{0,8}(我就|就)[^，。]{0,10}(封|停|限|关|冻|拉黑)",
  "clause": "COMMUNITY_3.4"
}
```

## 三、归因汇总

| 样本 | 归因层 | 根子 | 修法类别 |
|---|---|---|---|
| P01 | L1 | 短语表抓不住"关系" | **新增共现规则** |
| P03 | L3 | 阈值按开发集定，不符合真实会话长度 | 调阈值 |
| P04 | L1 | 短语表抓不住"句式" | **新增句式规则** |

**2 条是规则类型缺失（能力问题），1 条是阈值设定（参数问题）。**

这意味着：即使把词表从 12 条堆到 100 条，**P01 和 P04 仍然会漏**——
因为漏的不是"某个词没写"，是"这类表达方式根本没被支持"。

---

## 四、为什么 25% 这个数字仍然有价值

它准确指出了**瓶颈不在词表数量，在规则表达能力**：

| 假设 | 24 段标注上的证据 |
|---|---|
| 加词能提升 | 开发集 100% 是靠加词堆出来的，但留出集三只有 25% |
| 模型能兜住 | 模型没配，而且这类"关系型"判断小模型也未必稳 |
| 真正卡点 | 规则只支持"短语 + 权利/拒绝组合"，缺少"共现"和"句式" |

---

## 五、修复后怎么验证（关键）

**不能拿 holdout3 修完再拿 holdout3 汇报。** 那就变成第二次污染。

正确流程：

```
1. 实现共现规则 RX1 + 句式规则 RX2（对照 24 段开发集调，不碰 holdout3）
2. 重新跑 holdout3 → 看真实提升（这一次是"验证"，不是"调参"）
3. 无论结果好坏，holdout3 降级为开发集
4. 新建 holdout4（6 段全新场景），作为下一轮的诚实指标
```

**第 3 步是纪律**：一组数据只能当一次"没见过的数据"。

---

## 六、一句话总结

> **25% 不是"数据太少"，是"规则只会认短语，不会认关系"。**
> 这个结论只有靠一组没调过参的数据才能得出——这就是为什么我坚持建 holdout3。

---

## 七、为什么接上大模型不会自动解决这 3 条

直觉上对：这三条的**语义**模型能判。但实测发现，**其中 2 条根本不会走到模型**。

### 路由实测

| 样本 | 分流结果 | 说明 |
|---|---|---|
| P01 五星换运费 | **small（会调模型）** | 含风险词「五星」→ 交小模型 ✅ |
| P03 财务不在 | **rule（不调模型）** | 命中「反复拖延」→ 规则直接定 |
| P04 封号威胁 | **rule（不调模型）** | 无风险词 → 规则直接放行 ❌ |


outer.decide() 的判据是**关键词表**：

`python
RISK_WORDS = [验证码,身份证,加微信,转账,差评,好评,五星,评价,删,撤,...]
`

「你再闹我就让你这个号封了」里，**「封」不在表里** → 判为无风险信号 → 规则放行，模型一次都不会被调用。

### 有多少流量压根不进模型

当前 330 条判定的分流：

| 路径 | 条数 | 占比 | 会调模型吗 |
|---|---:|---:|---|
| 无风险规则放行 | 96 | 29% | ❌ |
| 高严重度直接定 | 60 | 18% | ❌ |
| 缓存命中 | 52 | 16% | ❌ |
| 含风险词交模型 | 33 | 10% | ✅ |
| 其余（人工等） | 89 | 27% | — |

**63% 的判定在设计上就不经过模型。** 模型再强，没被调用就等于不存在。

### 所以真正的修法不是接模型，是三件事

| # | 要改什么 | 为什么 |
|---|---|---|
| 1 | **路由判据** | 从关键词命中改成规则未命中但含交易/评价/威胁语境 |
| 2 | **传上下文** | P03 是跨轮累计问题，单句喂给模型也判不出 |
| 3 | **新的验证集** | 改完必须用没调过的数据测，否则又是一次自我欺骗 |

### 模型不是免费的

| 代价 | 现在 | 全量过模型 |
|---|---|---|
| 单条成本 | 0（规则） | 1~10 单位 |
| 延迟 | <1ms | 0.3–5s |
| 误报风险 | 0% | 未知，大概率上升 |
| 可解释性 | 有条款号 | 只有模型认为 |
| 注入风险 | 无 | 有（已加防护） |

**成本算术**：把 29% 的无风险放行改走小模型，成本从 0 变成约 0.29 单位/条，
延迟从 1ms 变成 500ms——**换来多少召回，现在测不出来**（没有 key）。

### 结论

> **模型补的是语义理解，补不了没被调用。**
> 这 3 条里，1 条是模型能救但没配 key，1 条是阈值问题（模型也要靠上下文），
> 1 条是路由问题——**它压根不进模型，接多少模型都没用。**
