# 数据处理规范

本规范约束配置数据、标注数据和运行数据。状态分为“已实现”和“待实现”，不把计划描述成现状。

## 1. 数据分类

| 数据 | 载体 | 来源 | 主要用途 | 状态 |
|---|---|---|---|---|
| 规则 | `data/rules.jsonl` | 人工维护 | 触发词、严重度、条款引用 | 已实现 |
| 条款 | `data/clauses.jsonl` | 人工维护 | 解释依据和建议动作 | 已实现 |
| 开发集 | `data/scenarios.jsonl` | 人工标注 | 调规则 | 已实现 |
| 历史留出集 | `holdout.jsonl` / `holdout2.jsonl` | 人工标注 | 历史复盘，不再作泛化证据 | 已实现 |
| 当前验收集 | `holdout3.jsonl` | 人工标注 | 未调参验收 | 已实现 |
| 判定日志 | `judge_logs` | 系统写入 | 判定、成本、延迟和标签 | 已实现 |
| 人工队列 | `review_queue` | 系统 + 人工 | 不确定样本与裁决 | 已实现 |
| 产品事件 | `events` | 客户端 + 服务端 | 曝光、点击、反馈、裁决 | 已实现 |
| 用户反馈 | `feedback` | 提醒卡按钮 | 质量和体验信号 | 已实现 |
| 配置缓存 | `decision_cache` | 系统 | 降低重复判定成本 | 已实现 |
| 图片/语音 | 外部附件 | 平台消息 | 内容理解 | 未实现 |

## 2. 标签语义

这是质量指标能够成立的前提：

| `truth_type` | 含义 | 进入召回/误报 |
|---|---|---|
| `NULL` | 未标注 | 否 |
| `正常沟通` | 已标注负样本 | 是 |
| 其他已登记类型 | 已标注正样本 | 是 |

禁止再用空字符串同时表示“未标注”和“正常”。随机生成器已为正常话术显式写入 `正常沟通`；历史兼容迁移会把普通手输的空标签转换为 `NULL`。

## 3. 标注集规则

### 3.1 集合用途

| 集合 | 能否调参 | 能否对外报泛化 |
|---|---|---|
| `scenarios` | 可以 | 不可以 |
| `holdout` | 不可以；历史上已违规调参 | 不可以 |
| `holdout2` | 不可以；历史上已违规调参 | 不可以 |
| `holdout3` | 不可以 | 可以，但必须同时报样本量 |

当前 holdout3 只有 4 条正例和 2 条负例。任何“0% 误报”“100% 类型准确”都必须同时披露 n，不得单独当结论。

### 3.2 字段约束

每段对话必须包含：

- 唯一 `id`
- 非空 `turns`
- 每轮 `role ∈ {user, merchant}`
- 每轮非空 `text`
- `expect.intervene`
- 应介入时提供合法的 `expect.turn` 和 `expect.type`

`validate_data.py` 还会检查 ID 与商家原话是否跨集合重复。重复检查只能发现显式泄漏，不能自动证明“人看过结果后改规则”的历史污染不存在，因此集合用途仍需流程管理。

## 4. 运行时处理

### 4.1 输入

```text
原文安全检查
  → NFKC 归一化
  → 空白与重复标点处理
  → 500 字截断（API 原上限 2000 字）
  → 判定
  → 落库前 PII 脱敏
```

安全检查必须发生在截断之前，否则超长输入可以绕过限制。提示注入命中后：

- 不自动放行。
- 不调用模型。
- 不读写判定缓存。
- 写入人工复核队列。

### 4.2 PII

当前落库前会屏蔽：

- 手机号
- 身份证号
- 银行卡号
- `sk-` 形式密钥

涉及 `judge_logs`、`review_queue`、`decision_cache`、`feedback` 和事件属性。响应中为了证据展示可能保留当前请求的原文，但数据库不保留对应未脱敏文本。

仍待实现：

- 身份证、地址、姓名等更完整的数据分类。
- 历史数据库回扫。
- 留存期限和自动删除。
- 字段级加密与访问审计。

## 5. 事务与连续性

本轮裁决在一个 SQLite 事务中完成：

1. 更新 `review_queue` 状态。
2. 生成 `cases` 介入单。
3. 写买家通知。
4. 更新商家违规次数。
5. 更新规则候选池。
6. 追加人工判定日志。

SQLite 使用 WAL、`busy_timeout` 和 `synchronous=NORMAL`。备份脚本使用官方 backup API，并在备份后执行 `PRAGMA integrity_check`。

这些能力不等于生产级高可用：SQLite 仍是单机单点，缺少自动故障切换。

## 7. 发布纪律

- 只能根据开发集和错误归因修规则。
- holdout3 只用于验收；失败样本进入缺陷清单，不在同一轮直接“看过再改”。
- 每轮评测记录数据集版本和规则文件哈希。
- 指标必须同时提供分子、分母、样本量和适用范围。
- 数据不足时输出“不可判定”，不能用 0% 或 100% 代替。
