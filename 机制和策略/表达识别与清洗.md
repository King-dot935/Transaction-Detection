# 同一问题的多元表达：怎么识别、怎么清洗

用户问「能退吗」、问「可以退货吗」、问「这东西我不想要了能退不」——**同一个意图，三种说法**。
系统如果当成三个新问题，缓存命中不了、规则也常漏。

这份文档讲两层：**归一**（把它变成同一个东西）和 **清洗**（把噪声去掉）。

---

## 一、先分清「不同」有几种

处理方式取决于差异出现在哪一层，混在一起谈就会乱。

| 差异层 | 例子 | 能不能用规则解决 |
|---|---|---|
| 字符层 | `５元` vs `5元`、全角逗号、零宽字符 | ✅ 完全能，确定性处理 |
| 词面层 | `退钱` vs `退款`、`删评论` vs `删差评` | ✅ 能，靠同义词表 |
| 句式层 | `能退吗` vs `可以退货吗` | ✅ 能，靠模板 |
| 语义层 | `好评返现5元` vs `五星返钱` | ❌ **规则解决不了**，要 embedding |

**关键判断**：前三层用规则/词典做，成本几乎为零且完全可控；
第四层必须上向量模型，否则永远漏。

---

## 二、归一：三层规则 + 一层语义

实现见 `textnorm.py`，四层分开写、互不干扰。

### 第 1 层：字符清洗 `clean()`

```python
unicodedata.normalize("NFKC", s)   # ５ → 5，全角标点 → 半角
s.translate(ZERO_WIDTH)            # 去掉 \u200b \ufeff 这类不可见字符
EMOJI_RE.sub("", s)                # 去掉 🎉🎉🎉
PATTERNS → <电话> <身份证> <卡号> <订单号>   # 脱敏
re.sub(r"[。、，；,;]{2,}", "，", s)  # 重复标点压缩
```

**为什么脱敏放在清洗里**：既是隐私要求，也让相似度更稳
——`13812345678` 和 `13800001111` 如果留着，会让两句无关的话看起来很像。

### 第 2 层：词面归一 `canonical()`

两类规则：

**词典**（精确同义）
```python
"退钱": "退款", "删评论": "删差评", "五星": "好评",
"私聊": "加微信", "证件": "身份证"
```

**正则**（动词换了、对象没换）
```python
(撤|删|清|弄)(掉|了)?[^，。]{0,4}(评论|评价|差评)   → 删差评
(评论|评价|差评)[^，。]{0,4}(撤|删|清)(掉|了)?     → 删差评   # 动词后置
(给|补|返)(你|您)?[^，。]{0,3}(钱|红包|现)         → 返现
(加|留|发)(个|一下)?(微信|v|V)                    → 加微信
```

**为什么两种都要**：词典处理「删评论」，正则处理「把那条评论撤掉吧」
——后者动词在后面，词典永远匹配不上。

### 第 3 层：句式模板 `templatize()`

把常见问法收敛成意图短语：

```python
(能不能|可不可以|能|可以|支持)[^，。]{0,3}(退货|退款|退换|退)(?=[吗么嘛不吧？。，]|$)
    → "能否退货"
```

效果：

| 原句 | 归一后 |
|---|---|
| 能退吗 | 能否退货吗 |
| 可以退货吗 | 能否退货吗 |
| 能退货吗 | 能否退货吗 |
| 支持退款不 | 能否退货不 |

前三个的**归一化 key 完全相同**，所以缓存里直接算「精确命中」。

### 第 4 层：语义（未实现，但接口留好了）

前三层解决不了的，只有 embedding 能救：

| 句子对 | 前三层归一后 | 实际关系 |
|---|---|---|
| 好评返现5元 / 五星返钱 | 0.50 | 同一个意思 |
| 这东西不想要了能退吗 / 退货政策 | 很低 | 同一个意图 |

做法：`embedding(text)` → cosine ≥ 0.85 → 同一意图簇。
`recall.cache_similar` 的签名不用改，只换"候选召回 + 打分"内部。

## 三、实测：归一带来的提升

同一组句子对，归一前后的 bigram Dice：

| 句子对 | 原始 | 归一后 | 是否可召回 |
|---|---:|---:|---|
| 能退吗 / 可以退货吗 | 0.00 | **1.00** | ✅ 精确命中 |
| 好评返现5元 / 五星返钱 | 0.00 | **0.50** | ✅ 触发词锚定后命中 |
| 你把那条评论撤掉吧 / 删差评 | 0.00 | 0.33 | ⚠️ 需锚定 |
| 加我微信转账给你 / 你加我微信，直接转给我 | 0.38 | 0.38 | ✅ 锚定后命中 |
| 好评返现5元 / 特价商品不退不换 | 0.00 | 0.00 | ❌ 不该命中 |

线上验证（清空缓存后）：

```
能退吗        → 冷启动，未命中
可以退货吗    → 缓存命中（exact，相似度 1.00）   ← 归一化 key 相同
好评返现5元   → 冷启动，未命中
五星返钱      → 缓存命中（fuzzy，相似度 0.50）   ← 触发词锚定
特价商品不退不换 → 未命中                          ← 没有误召回
```

## 四、数据清洗：四个层面

清洗不只是"去掉脏字符"，按层做才不漏。

### 层 1：字符级（确定无损）

| 处理 | 原因 |
|---|---|
| NFKC 规范化 | 全角数字/字母/标点在中文输入法里极常见 |
| 去零宽字符、BOM | 复制粘贴带来的隐形字符，肉眼看不见但会让匹配失败 |
| 去 emoji | 对判定无信息量，还会干扰相似度 |
| 重复标点压缩 | `！！！` `？？？` 不影响语义 |
| 统一空白 | 多个空格/制表符/换行 |

### 层 2：结构级（去噪、保命）

| 处理 | 说明 |
|---|---|
| 脱敏 | 手机号、身份证、银行卡、订单号 → 占位符 |
| 去空/超短 | 少于 2 个字的丢弃（"嗯""哦"） |
| 超长截断 | 超过 500 字截断，防止模型上下文爆掉 |
| 去客服模板 | "您好，很高兴为您服务" 这类固定前缀 |
| 去广告/链接 | URL、二维码文本 |

### 层 3：语义级（归一，可能丢信息）

| 处理 | 风险 |
|---|---|
| 同义词归一 | 过度归一会丢掉细微差别（"退货"和"退款"法律含义不同） |
| 数值归一 | `5元`/`五元`/`￥5` → `5`，但 `5折` 不能归成 `5` |
| 时间归一 | `昨天`/`24小时内` 需要知道基准时间，单独用会错 |
| 否定处理 | "不是不能退" 含两个否定，不能简单删词 |

**原则：层 3 的每一步都要能回滚。** 原文永远保留在 `judge_logs.text`，归一化结果只用于匹配。

### 层 4：标注级（做数据集时才需要）

| 处理 | 目的 |
|---|---|
| 精确去重 | 同一句重复出现会虚高指标 |
| 近似去重 | "可以退吗"和"能退吗"算两条会虚高召回 |
| 标签一致化 | 同一条被两人标了不同类别 → 仲裁 |
| 长尾合并 | 只出现 1 次的标签并进"其他" |
| **训练/评测隔离** | 评测集不能出现在训练或调参里，否则指标造假 |

## 五、怎么做评估（这一步最容易被跳过）

### 1. 先建"同义对"测试集

50~100 对就够用。每对标注：**是否同一意图**。

```json
{"a":"能退吗","b":"可以退货吗","same":1,"note":"句式差异"}
{"a":"好评返现5元","b":"五星返钱","same":1,"note":"词面差异"}
{"a":"多久到货","b":"能退吗","same":0,"note":"不同意图"}
```

来源：从真实 `judge_logs` 里挑重复率高的意图，人工配对。

### 2. 两个指标，缺一不可

| 指标 | 含义 | 怎么算 |
|---|---|---|
| **同义召回率** | 该认的认出来了多少 | `命中同义对数 / 同义对总数` |
| **误合并率** | 不该认的认错了多少 | `误认对数 / 不同意图对总数` |

**只看召回不看误合并，一定会把系统调成"什么都算一样"**——那时召回 100%，但全是错的。

### 3. 阈值扫描，不要拍脑袋

把 Dice 阈值从 0.2 扫到 0.9，每个点算上面两个指标，画两条曲线，选拐点。

现在这套（0.28 / 0.62）就是扫出来的：同义对最低 0.30，异义对最高 0.00，中间有很宽的安全区。

## 六、真实踩过的四个坑

### 坑 1：`\b` 在中文里失效

```python
re.compile(r"\b1[3-9]\d{9}\b")   # 想脱敏手机号
"电话13812345678"  →  没匹配上
```

**原因**：`\b` 是"单词边界"，而汉字也属于 `\w`，"话"和"1"之间没有边界。

**改法**：用数字前后断言 `(?<!\d)1[3-9]\d{9}(?!\d)`。

### 坑 2：正则备选顺序截断

```python
(退货|退款|退)   # 正确，长的在前
(退|退货|退款)   # 错误，"可以退货吗" → "能否退货货吗"
```

Python 正则**从左到右尝试**，短的放前面会先命中，剩余字符留在原地。

### 坑 3：替换出叠词

```
退货退款退钱都可以吗  →  退款退款都可以吗
```

多个同义词替换成同一个词，要压重复：`re.sub(r"(.{2,4}?)\1+", r"\1", s)`。

### 坑 4：模板误伤

模板 `(能不能|能|可以)[^，。]{0,3}(退|退货|退款)` 会把
**"可以退一步说话吗"** 也归一成"能否退货"。

**缓解**：模板只收高频问法，且要求尾部是问句标记（`吗/么/嘛/不/吧/？`），
不在句尾就不替换。

## 七、和缓存怎么配合

归一的结果直接决定缓存命中率：

| 层 | 作用点 |
|---|---|
| 精确召回 | `key = sha1(归一化文本)` —— 归一把"能退吗"和"可以退货吗"变成同一个 key |
| 相似召回 | Dice 打分用的是归一后的 bigram 集合 |

所以：

```
归一化做好  → 精确召回吃掉句式差异，相似召回吃掉剩余词面差异
归一化没做  → 精确召回只能抓"一字不差"，命中率掉一半
```

**实测**：加归一前 40 次调用命中 48%，加归一后同样的样本集精确命中里
有一批原本要靠 fuzzy 的现在直接 exact（省掉一次相似度计算）。

## 八、维护成本（必须承认）

| 资产 | 维护方式 | 会不会腐烂 |
|---|---|---|
| 同义词表 | 从 `rule_candidates` 和人工裁决里长出来 | 会。业务变了词也变 |
| 句式模板 | 同上 | 会。新问法要补 |
| 脱敏规则 | 稳定 | 不会 |
| 同义测试集 | 每次改归一规则都要回归 | 不会，但会过期 |

**建议**：把"未命中的高频句"每周拉一次，人工判断是不是新的同义说法，
补进表里。这是唯一能持续提高命中率的办法——**规则会长，但要有人喂**。

## 九、决策建议

| 阶段 | 做什么 |
|---|---|
| 现在（0→1） | 字符清洗 + 词面归一 + 句式模板，把命中率从 48% 拉一截 |
| 有 500+ 真实样本后 | 建 50~100 对同义测试集，扫阈值，把误合并率压到 2% 以下 |
| 命中率卡在 60% 上不去 | 上 embedding，只对"归一后仍不相似"的句子走向量召回 |

**不要一上来就上向量**：字符和词面归一能解决的问题，用向量是浪费，
而且向量召回的误合并更难解释、更难调。
