### 标注是怎么设计的

不是随机采样，是**按缺陷类型配额设计**：

| 类型 | 覆盖 | 设计意图 |
|---|---:|---|
| 拒绝法定权利 | 4 | 最常见的违规 |
| 以利益换好评 | 4 | 表述变化最多 |
| 诱导线下交易 | 3 | 高风险，需早期发现 |
| 扩大退货例外 | 3 | 与"拒绝法定权利"易混淆 |
| 威胁或辱骂 | 2 | 高严重度 |
| 反复拖延 | 2 | 需要多轮累计才成立 |
| 拒绝开票 | 2 | 独立条款 |
| 索要身份信息 | 2 | 隐私类 |
| 诱导放弃权利 | 2 | 引用条款型 |
| **正常沟通（负例）** | 6 | 压误报 |

每条标注三个字段：

```json
{"expect": {"intervene": true, "type": "以利益换好评", "turn": 1}}
```

`turn` 是**第几轮该发现**——判对了类型但第 5 轮才发现，对用户已经晚了。

## 三、指标血缘：每个数字从哪来

| 指标 | 计算位置 | 数据来源 | 公式 |
|---|---|---|---|
| 召回率 | `run_eval.py:19 evaluate_set` | 四组标注的 `expect.intervene` vs `detector.analyze()` | TP/(TP+FN) |
| 误报率 | 同上 | `expect.intervene=false` vs 实际 | FP/(FP+TN) |
| 类型准确率 | 同上 | `expect.type` vs `first["type"]` | 类型对/TP |
| 首轮位置 | 同上 | `first["turn"]` | 平均轮次 |
| 切片指标 | `eval_suite.py:47 slice_metrics` | 上面的 rows 再按维度分桶 | 同上的分桶版 |
| 缺陷清单 | `eval_suite.py:75 badcases` | rows 里 `want≠got` 或 `type≠type` | — |
| 在线信号 | `eval_suite.py:96 online_metrics` | `judge_logs` / `review_queue` / `feedback` | 见下 |
| 门禁结论 | `run_eval.py:124 gate` | 四组召回 + 误报 | 阈值卡口 |
| 聚类结果 | `badcase_cluster.py:136 cluster` | 离线失败 + 线上翻转 + 用户误报 | 余弦 ≥ 0.42 合并 |

### 在线信号的三个公式

```python
缓存命中率   = count(judge_logs.route_reason LIKE '缓存命中%') / count(judge_logs)
待复核率     = count(review_queue) / count(judge_logs)
人工不一致率 = count(review_queue WHERE (rule_hit=1) ≠ (status='approved')) / count(已裁决)
```

**注意分子的分母不同**：待复核率的分母是"判定总量"，
人工不一致率的分母是"已裁决的复核条目"——因为没裁决的还不知道对错。

## 四、切片维度（`eval_suite.py:27,29`）

| 维度 | 取值 | 为什么切 |
|---|---|---|
| 类型 | 10 个意图类型 | 找出"哪类判最差" |
| 句长 | ≤10 / 11–20 / >20 | 长句是否更容易漏 |
| 含条款词 | 是/否（规定/条款/原则上/除非…） | 引用条款的句子规则最容易漏 |

实跑举例：

```
最弱切片：
  类型:以利益换好评   召回 33%（样本 3）
  句长:中句 11-20     召回 67%（样本 6）
```

## 六、完整运行流程

```
python eval_all.py
   │
   ├─ eval_suite.py
   │    ├─ 读 4 组标注 → 跑 detector → 算指标
   │    ├─ 切片（类型/句长/条款词）
   │    ├─ 提取缺陷清单
   │    ├─ 读 judge_logs/review_queue/feedback → 在线信号
   │    ├─ 写 eval_runs（一行历史）
   │    └─ 输出 评测报告.md
   │
   ├─ badcase_cluster.py
   │    ├─ 池子 = 离线失败 + 线上人工翻转 + 用户误报
   │    ├─ 字 bigram + TF-IDF → 余弦 → Union-Find
   │    └─ 输出 badcase_clusters.md
   │
   └─ run_eval.py
        ├─ 四组召回 + 误报
        ├─ 与 GATE 比对
        └─ 输出 eval_report.md；不过则退出码 1
```

## 七、可复现性

| 关注点 | 做法 |
|---|---|
| 结果可复现 | 规则引擎无随机数；聚类用 Union-Find，无随机初始化 |
| 历史可追溯 | 每次跑写 `eval_runs`，能看指标随版本的走势 |
| 回归可对比 | `eval_suite.save_run` 取上一条，逐项对比 ↑ / ↓ |
| CI 可接入 | `eval_all.py` 退出码即结论 |

## 八、这套体系的已知缺口

| 缺口 | 现状 | 影响 |
|---|---|---|
| 标注量太小 | 30 段（24+6） | 每类只有 2–4 条，指标置信度低 |
| 负例太少 | 8 条 | "误报 0%" 统计上不成立 |
| 标注是设计的，不是真实分布 | 手写 | 线上真实长尾可能完全没覆盖 |
| 没有人工标注一致性检查 | 单人标注 | 无法判断标签本身是否可靠 |
| 在线样本少 | 281 条判定、1 条反馈 | 在线信号只能看趋势，不能下结论 |
| 聚类用字符相似 | 未接 embedding | 同义不同词会漏聚 |

### 补齐优先级

| 顺序 | 动作 | 收益 |
|---:|---|---|
| 1 | 负例从 8 条扩到 50 条 | 让"误报率"这个指标真正可用 |
| 2 | 从 `rule_candidates`（17 条）抽真实话术补标注 | 让分布接近线上 |
| 3 | 每类型补到 ≥10 条 | 切片指标才有统计意义 |
| 4 | 前端加埋点（点击/跳过/误报） | 从"判得准"扩到"好不好用" |

---

## 九、一句话总结

> 这套体系的骨架是完整的（数据 → 指标 → 切片 → 缺陷 → 聚类 → 门禁 → 回归），
> **但血肉很薄**——30 段标注、8 条负例、1 条用户反馈。
> 它现在能做的是"防止我自我欺骗"，还做不到"预测线上表现"。
